# 後續規劃

先把現在這套課程與會員網站做好用，再依實際使用經驗逐步簡化。維護者自用和外部自架使用同一份程式，修正也回到同一條開發主線；原則見 [PRINCIPLES](../../PRINCIPLES.md)。

## 第一版的重點

- 能用自己的帳號與設定，從零啟動單一執行個體的 PostgreSQL／本機儲存部署。
- 課程、會員存取、管理後台與中性示範內容有清楚的操作與測試入口。
- 安裝、備份、還原與升級能照文件執行，遇到問題也找得到排查方式。
- 人與 AI 都能找到程式位置、功能規則、必要設定與測試，不依賴維護者的私人環境。

程式已在 [cablate/cabai](https://github.com/cablate/cabai) 公開，私人漏洞回報入口也已啟用；第一個版本發布仍在準備中。首次公開 CI 的瀏覽器失敗已修正，兩種品牌的隔離安裝與[更新版 GitHub CI](https://github.com/cablate/cabai/actions/runs/37858915352) 均已通過；本批結果見[自架首次成功計畫](SELF-HOSTING-FIRST-SUCCESS.md)。接下來依下列優先序改善，不把正式站切換混入公開程式更新。既有驗證範圍與尚未涵蓋的情境見[開發與測試](../development/DEVELOPMENT-AND-TESTING.md#first-release-verification-scope-2026-10-08)。

## 接著優先改善什麼？

1. **減少安裝卡關。** 收集去識別化的安裝問題，優先修正預設設定、錯誤訊息與教學中不清楚的步驟。
2. **讓 AI 連線更容易。** 補齊 User Agent token 的本機設定引導，讓第一次連線不必猜環境變數放在哪。細節見[首次連線規格](../contracts/user-agent-first-success.md)。
3. **讓升級更可預期。** 用同一主線在維護者站點實際使用，驗證現有資料升級與資料庫／檔案成對還原，把修正回饋到公共流程。
4. **逐一驗證選用服務。** Google 登入、付款、郵件、Discord 與 R2 各自有帳號和環境設定；以測試環境補足完整流程，再擴大支援範圍。
5. **依使用經驗做減法。** 評估哪些概念、入口或操作可以合併。包含課程與 Skill 的關係，但不預先決定刪除某種功能，也不讓全面重寫阻擋小版本交付。

## 目前不擴大的範圍

多租戶、所有內容型態的全面重設、多副本部署，以及大量新整合，都不是第一版前提。既有購買權益、退款撤權、私有內容保護和資料恢復，則是每次改動都要保留的基本行為。

Legacy Marketplace 目前停用；既有使用者的影響與人工對帳方式見[設定說明](../development/CONFIGURATION.md#legacy-marketplace-unavailable-in-the-first-release)。正式站切換需要另外驗證自己的登入、付款、既有資料與還原流程，不與 repo 發布合併成同一步。

每次改善以一個可以驗收的小成果為單位：說清楚誰遇到什麼問題、修改哪個現有功能、如何測試，以及舊使用者需要做什麼。
