# CabAI — 架一個自己的課程與會員網站
[English](README.md)

![CabAI — knowledge for people and AI](design/banner/banner-desktop.png)

CabAI 是一套可以自己架設的課程與會員網站，適合想把教材放在自己的網站上、自己管理學員的創作者。

你可以在後台編寫課程、整理章節，讓訪客先看試閱，再讓有權限的會員閱讀完整內容。學員登入後，可以找到自己的課程、接著上次的進度繼續學習；你則在同一個後台管理內容和會員的存取權限。

網站名稱、教材、會員資料和使用的服務帳號都由你自己管理。你也可以透過 Agent API，讓 AI 協助操作內容，不必每次都手動點後台。

## 可以拿來做什麼？

- **把教材整理成課程。** 用章節和單元安排內容，分開管理草稿、已發布內容與試閱。
- **讓會員找到自己的教材。** 學員有自己的課程入口，可以閱讀內容並記錄完成進度。
- **決定誰能看哪些內容。** 管理會員的課程權限，讓公開試閱和會員專屬內容放在同一個網站。
- **依需要接上外部服務。** 例如付款、郵件或 Discord；先把課程網站架起來，再設定需要的整合。

例如，你可以先做一門三個單元的小課，開放第一個單元試閱，再把完整課程提供給加入的會員。不需要一開始就設定付款或郵件服務。

## 先在自己的電腦試試

專案附了一門範例課程，有 **2 個章節、3 個單元**。你可以先看網站長什麼樣子，再進後台試著編輯內容。

準備 Node.js 22、npm、Docker 和 Git，接著照[開始使用](docs/development/GETTING-STARTED.md)完成設定、啟動資料庫並載入範例。完成後開啟 `http://localhost:3000`，就能看到課程與試閱頁面。

試看範例不用申請外部服務。第一次進後台有專用的管理員建立流程；要讓學員用 Google 登入時，再設定你自己的 Google 登入憑證。請用新建的資料庫試用範例，與正式會員資料分開。

想放上自己的網域、讓其他人使用？接著看[部署與維運](docs/operations/DEPLOYMENT-AND-OPERATIONS.md)。目前文件以一台 Linux 主機搭配 PostgreSQL 和本機檔案儲存為起點，包含 HTTPS、備份還原與升級方式。主機、網域及選用服務的費用由你自行負擔。

## 也可以請你的 AI 幫忙架

把這個 repo 的連結交給能讀取檔案、執行指令的 AI 助理，再貼上這段話：

> 我想架設 CabAI。請先讀 README.md 和 AGENTS.md，再依專案文件帶我完成。先問我想在電腦上試用，還是部署到主機；確認環境後，告訴我需要準備哪些帳號與設定。使用我自己的服務帳號，密鑰留在本機設定檔。需要動到既有資料、付費服務或正式網站時，先跟我確認。完成後帶我檢查網站、登入與課程權限，並告訴我怎麼備份、還原和升級；還沒測到的部分也請列出來。

[AGENTS.md](AGENTS.md) 是給 AI 的導覽，會指出設定、程式碼、測試和部署文件的位置。你不用先讀懂整套程式；AI 可以照文件操作，遇到需要你提供的主機權限或帳號設定時再請你協助。

## 自己用，也一起改好

這個專案採用 **dogfooding** 的方向：維護者自用和大家下載的版本共用同一套程式，自己使用時遇到的問題，也回到這個 repo 修正。不同網站的品牌、帳號與資料用設定區分，讓後續改善能一起受益。完整原則寫在 [PRINCIPLES](PRINCIPLES.md)。

程式使用 Next.js、TypeScript 和 PostgreSQL。想調整外觀、擴充功能或串接自己的工具，可以從[模組地圖](docs/architecture/MODULE-MAP.md)和[貢獻指南](CONTRIBUTING.md)開始；執行測試請看[開發與測試](docs/development/DEVELOPMENT-AND-TESTING.md)。

目前正在準備第一個公開版本，主要流程是課程發布與會員閱讀，已完成本機建置、瀏覽器流程及備份還原測試。正式使用前，請在自己的環境走一遍登入與課程流程，並測試要啟用的外部服務。接下來會先改善安裝和日常使用遇到的問題，規劃見 [ROADMAP](docs/planning/ROADMAP.md)。
